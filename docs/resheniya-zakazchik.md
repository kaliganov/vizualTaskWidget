## Зафиксировано

| Тема | Решение |
|------|---------|
| Суть продукта | Сетевой график (схема путей) + канбан; видно, куда движется команда |
| Первое демо | **И схема, и канбан** сразу |
| Срок демо | Без жёсткой даты |
| Успех демо | Основатель собрал схему → назначил ответственных → ответственные оценили время и внесли на схему → схема «ожила» |
| Пользователи | Вся команда |
| Число людей на цель | Без лимита (технически заложить запас) |
| Компании в тесте | Одна тестовая |
| Роли/доступы в v1 | Не нужны (все могут всё) |
| Подпись на стрелке | Время выполнения **предыдущей** задачи |
| Старт следующей до Done предыдущей | **Да**, задачи независимы |
| Пути | Без именованных дорожек — линии задач сами читаются как пути |
| Ввод планов | Руками **и** импорт из Excel |
| Колонки канбана | 4 шт., как в ТЗ — ок |
| На карточке must | название, описание, ответственные, срок, приоритет, чек-лист, комментарии, учёт времени, **файлы**, **история** |
| Метки (теги) | Не обязательны в первом демо |
| WIP-лимиты | Не нужны |
| Assignees | Пока свои учётки тестового приложения |
| В portal потом | Отдельный пункт меню, все сотрудники |
| Связь с задачами portal | Отдельный мир |
| Дизайн | Свой аккуратный вид |
| Хостинг демо | Компьютер разработчика |
| Язык | Только русский |
| Приёмка | Заказчик сам |
| Пример для демо | «Постройка дома для продажи» |

## Вопрос 11 — простыми словами (нужен повторный ответ)

**«Веха»** — это точка на схеме вроде «Фундамент готов» или «Получено разрешение».  
На неё **не открывается канбан** (нет доски с карточками). Это просто отметка: «этот момент наступил».

Обычная **задача** — кружок, по двойному клику открывается доска.

**Вопрос заказчику ещё раз:**  
В первой версии нужны такие «галочки-даты» без доски, или хватит только обычных задач + финальной цели?

**Пока в разработке:** только задачи + цель (вехи не делаем, пока не скажут иначе).

## На что обратить внимание (риски)

1. **Объём первого демо очень большой:** схема + полный канбан (включая файлы и историю) + импорт Excel. Это дольше, чем «пощупать идею» в урезанном MVP.  
2. **Успех демо** завязан на назначение людей и оценки времени на схеме — это must для Phase 2–3, не «потом».  
3. **«Запускать с портала на рабочем столе»** — уточнить отдельно: сейчас standalone на ПК разработчика; ярлык/запуск с portal — уже этап виджета.  
4. **«Без ограничений» по людям** vs одна тестовая компания — для теста ок; в коде не ставить искусственный лимит «5 человек», но и не обещать сразу 500 без проверки.  
5. **Файлы** на локальном демо — нужны папка/хранилище на машине разработчика (или простой upload на диск сервера API).

## Рекомендуемый порядок работ (с учётом ответов)

1. Схема: узлы, стрелки с длительностью предыдущей, назначения, оценки → схема «живая».  
2. Канбан узла: must-поля с карточки (без меток и WIP).  
3. Импорт Excel (шаблон столбцов согласовать).  
4. Файлы + история (можно чуть после базового канбана, если упрёмся в срок).  
5. Демо на примере «Постройка дома для продажи».

## Осталось уточнить одним сообщением заказчику

1. Вехи — нужны или нет (см. выше).  
2. Импорт Excel: есть ли уже таблица-образец или нарисовать шаблон сами?  
3. «С портала на рабочий стол» — это про будущее в portal или уже про первое демо?
